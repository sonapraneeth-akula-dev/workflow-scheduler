Glossary: terms in this diagram
LLD / write path
Low-level design: the exact route a change takes through programs, database tables and file storage.
workflow.cs / SDK / describe / manifest
A C# workflow file uses the software development kit (SDK). Describe reads its structure into manifest.json, a machine-readable description.
wf publish / CI/CD / CLI / registration
The command-line interface (CLI) publishes a workflow version; an automated continuous integration and delivery (CI/CD) job checks and registers it.
Registry tables / packages/ / SHA-256
Registry tables track registered versions and schedules; packages/ stores compiled workflow files named by their SHA-256 content fingerprint.
API / POST /api/v1/registrations / HTTPS
The application programming interface (API) accepts registration at this web address; HTTPS encrypts the request.
Upload grant / immutable package
A grant gives temporary permission to upload a file; an immutable package cannot be changed after publication.
Trigger / Abort / Rerun / idempotency key
Start, stop or repeat a run. An idempotency key prevents an accidentally repeated request from creating duplicate work.
UI / commands / SQL / INSERT / NOTIFY / transaction
The user interface (UI) or API requests an action. The API adds a command row using database language (SQL INSERT) and signals the engine (NOTIFY) in one transaction: both succeed together or neither does.
Upsert / project
Upsert inserts a new record or updates an existing one; project applies recorded events to current-state tables.
Engine leader / run actor / single writer
The active engine schedules work. A run actor manages one run; only that engine writes run state, avoiding conflicting updates.
run_events / append-only / protobuf / seq
Permanent ordered records of changes to a run. Protocol Buffers (protobuf) stores them compactly; seq is their sequence number.
Snapshot tables / runs / node_runs / task_attempts
Tables holding the current status of a run, its steps (nodes), and each attempt to execute a task; updated with the event in the same transaction.
DB / ⧉ / partition
DB means database. Tables marked ⧉ are divided by month so old run data can be found or removed more efficiently.
Dispatch / Result / gRPC / agent journal
The engine sends a task to an agent over gRPC, a two-way messaging connection; the agent reports its result and keeps a disk copy until the engine confirms receipt.
Task host / UDS / ctx / outputs / checkpoint
A separate process executes tasks and sends outputs to its agent over a Unix domain socket (UDS). ctx means task context, the data and services provided to a task; a checkpoint saves progress for a later retry.
Run blobs / logs/ / resources/ / reports/ / artifacts/ / checkpoints/
Large files stored outside the database: task messages, CPU/memory samples, readable reports, downloaded files and saved task progress.
perf/ / histograms / parity/
Performance measurement distributions and saved examples of differences between baseline and candidate results.
Pointer row / blob_uri
A database row containing the location of a stored file rather than the entire file.
Scheduler / heap / next_fire_at / schedule_fires / PK / ON CONFLICT
The scheduler keeps due times in a heap (a queue ordered by the next due time, next_fire_at). A primary key (PK) on schedule and time in schedule_fires and ON CONFLICT prevent recording the same scheduled time twice.
Arrows / same-transaction box
Arrows show who writes or signals whom; the dashed box marks writes committed together or rolled back together.
